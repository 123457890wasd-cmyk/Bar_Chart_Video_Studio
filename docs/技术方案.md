# 自动统计视频工具(Bar Chart Race)技术方案

> 版本:v1.1 · 状态:需求已确认(见 §11 决策记录) · 读者:开发者/出资方
> 产品一句话:**导入一段"时间 × 实体 × 数值"的统计表,自动生成一条条形图随时间变化的动态视频(即 bar chart race),可导出 mp4 用于发布。**

---

## 0. 结论摘要(TL;DR)

| 决策点 | 结论 | 理由 |
|---|---|---|
| 产品形态 | Web 应用:数据导入 → 配置 → 预览 → 一键导出视频 | 渲染与录屏都在浏览器完成,免服务器算力 |
| 运行形态 | **单机单用户**,无账号/鉴权 | 已确认(§11) |
| 前端 | Vue 3 + Vite + TypeScript,自研 Canvas 2D 渲染内核 | 你已选定 Vue 3;自研渲染内核才能对"时间轴 + 排序过渡 + 录屏"做完全控制 |
| 后端 | Node.js + TypeScript + Fastify + Prisma(Drizzle 亦可) | 与前端同构,一个语言栈;本项目后端很薄,主要管数据和 DeepSeek 转发 |
| 数据库 | **SQLite(唯一数据库)**,DDL 仍按可移植口径编写 | 已确认单机单用户,无需 PostgreSQL;单文件零配置、易备份 |
| 数据来源 | ① 政府公开数据库(按具体视频主题选源:下载文件 / URL 抓取)② 本地导入 **Excel(.xlsx)/CSV** | 已确认(§11);"政府源"做成数据源适配层,不绑定具体机构 |
| 视频生成 | 浏览器内 Canvas 动画 + `canvas.captureStream()` + `MediaRecorder` 录屏,输出 WebM;再用 `ffmpeg.wasm` 原地转 mp4 | 你已选定浏览器渲染;默认导出 **横屏 1920×1080@30fps**(注:1080×1920 为竖屏,需要则切换预设) |
| 动画算法 | 值线性插值 + 按插值结果排序定 Y 位置,条形平滑移动;时间标签独立走时间轴 | 详见 §6 |
| 音频 | **本项目不做音轨/字幕**,由后期视频剪辑软件合成 | 已确认(§11),避免 MediaRecorder 无系统音频与合成复杂度 |
| AI 的定位 | 开发期:AI 辅助写代码;产品内:AI 能力作二期插件,默认接 **DeepSeek**(OpenAI 兼容 API) | 已确认(§11);详见 §3.7 / §8 阶段4 |

**一句话架构**:Vue 前端从 SQL 拉取时序数据 → 内存中构建"帧序列" → Canvas 渲染引擎按时间轴播放条形图动画 → 录制时引擎把同一画面画到隐藏的高清画布 → MediaRecorder 录成视频文件 → 前端就地转码、下载。

## 1. 需求理解

### 1.1 目标画面(对标常见 YouTube "barchart race" 视频)

- 横条(或竖条)排行榜,条的长度 = 数值,条的颜色 = 实体固定色;
- 时间推进时,各条的数值变化 → 长度变化,实体之间的**排名实时升降**,条平滑上下滑动交换位置;
- 画面角落(通常左上/右上)**时间标签实时变化**(如 1950 → 1951 … 或 第1季度 → 第2季度);
- 顶部大标题、轴标签、数值文本、数据来源角标可选;
- 最终产物是一段 mp4 视频(用户发布到 B 站/抖音/YouTube/视频号等)。

### 1.2 输入数据形状(本方案的"标准模型")

每条记录 = **(时间, 实体, 数值)**。例如:

| time | entity | value |
|---|---|---|
| 2019 | 苹果 | 260 |
| 2019 | 微软 | 125 |
| 2020 | 苹果 | 274 |
| 2020 | 微软 | 166 |

- `time` 可以是年份、月份、季度、任何可分段的标签(不要求连续、不要求等距);
- `entity` 是参与排行的条(实体),如国家/公司/UP主;
- `value` 是该时刻的统计数值。
- 若原始数据是"每个实体一列"的宽表(CSV 常见),由导入器转成上面的长表。

### 1.3 功能范围

**MVP(第 0–3 阶段,必做)**

1. 新建项目、导入 **Excel(.xlsx)/CSV** 或粘贴表格(也可从"政府公开数据源"填入文件 URL 抓取),预览与编辑原始数据;
2. 时间轴回放:播放/暂停/变速/拖动进度;
3. 视觉配置:标题、条数上限、配色、字号、分辨率、每段时间、是否显示数值等;
4. 一键录制并导出 mp4(含进度反馈);
5. 作品记录列表:已生成视频可回看/重下。

**增强(第 4 阶段,可选,按需裁剪)**

6. AI 辅助(接 DeepSeek):一句话生成示例数据、自动挑配色、生成标题/文案、检测异常值;
7. ~~音轨/字幕合成~~ —— **已排除**:音频由外部视频剪辑软件后期合成(§11),本项目只出无声成片;
8. 批量出片、定时任务(仅当后端渲染被重新引入时才真正需要)。

### 2.2 分层职责

| 层 | 职责 | 明确不做 |
|---|---|---|
| 数据导入层(前端/后端均可) | CSV/JSON 解析、类型校验、宽表→长表、缺失值策略 | 复杂 ETL |
| 业务数据层(SQL) | 项目、时序数据、配置快照、作品记录持久化 | 存视频大文件(存磁盘路径/对象存储 URL) |
| API 层(Node) | 资源的 CRUD、CSV 上传、录制产物登记 | 渲染/转码(浏览器端做) |
| 渲染引擎(Vue/Canvas) | 把帧序列画成条形图动画 | 与 DOM 图表库耦合 |
| 时间轴/录屏(Vue) | 播放控制;把同一引擎输出到隐藏高清画布录制 | —— |
| 转码(ffmpeg.wasm) | WebM → mp4(H.264) | 音频(可选后再加) |

### 2.3 为什么"渲染 + 录屏"放浏览器(以及代价)

已选定此路线,设计上注意三点补偿:

1. **录屏 = 二次渲染**:预览画布与"导出画布"分开。录制期间用隐藏的 1920×1080 画布重绘(引擎是无 DOM 依赖的纯函数式 draw(frame, ctx)),保证导出画质与预览操作(拖拽、鼠标悬停)互不干扰。
2. **转码放本地**:`MediaRecorder` 只产出 WebM(VP8/VP9),发布平台普遍要 mp4;用 `ffmpeg.wasm`(WASM 单线程版本 ~30MB)在浏览器内转 H.264,避免上传服务器。备选:直接产出 `video/mp4; codecs=h264` 的 WebM 容器并不通用,不推荐。
3. **性能隔离**:录制任务放在独立的渲染循环里(见 §6.3),与 UI 动画循环解耦,避免 UI 卡顿导致掉帧。

## 3. 前端设计(Vue 3)

### 3.1 选型清单与理由

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | Vue 3 `<script setup>` + Vite + TypeScript | 已选定;Vite 冷启动快 |
| 状态 | Pinia | Vue 官方生态,存"当前项目/数据/配置" |
| 路由 | Vue Router | 三页结构 |

| 国际化/主题 | 不做首版;主题色仅做配置项 | —— |

### 3.2 页面结构(3 页)

1. **工作台/数据页**(`/` 与 `/projects/:id/data`)
   - 项目列表(卡片:标题、更新时间、是否已有成片);
   - 新建项目 → 导入 CSV/粘贴表格/手动录入;
   - 导入后数据校验报告(无法解析的数值、缺失时间等),转换结果表格预览;
   - 选择"哪一列是 time / entity / value",自动猜列头。
2. **编辑器页**(`/projects/:id/edit`)
   - 左侧配置面板(表单):标题、副标题、条数上限、时长/每段时间、颜色方案、是否显示数值、字号档、背景色、来源角标、时间标签格式;
   - 右侧 Canvas 预览区:播放/暂停/单步/变速(0.5×/1×/2×)/进度条;
   - 配置即改即生效(动画面板暂存,不立即写库,"保存"才落库)。
3. **导出页/作品页**(`/projects/:id/export`)
   - 导出设置:分辨率(默认 1920×1080)、帧率(默认 30)、码率档;
   - 开始导出 → 进度(渲染帧数/转码百分比);
   - 完成后预览 mp4、下载、命名保存到作品记录。

### 3.3 Canvas 渲染引擎设计(核心)

**引擎形态**:一个与 Vue 无关的 TS 模块 `BarRaceRenderer`。输入:帧序列 + 渲染选项;输出:一帧画面到任意 `CanvasRenderingContext2D`。这样"预览画布"和"录制画布"共用同一个引擎,只是帧率与尺寸参数不同。

```ts
// 核心接口(设计草案)
interface FrameSpec {
  timeIndex: number;      // 当前位于第几个时间点(可为小数=插值中)
  timeLabel: string;      // 由外部按插值结果算好(如 "2020.5 年"? 见 §6.2)
}

interface RenderOptions {
  width: number; height: number;
  title?: string; subtitle?: string;
  maxBars: number;                 // 只显示前 N 名
  colors: (entity: string) => string;
  showValues: boolean;
  timeLabelPos: 'top-left' | 'top-right' | 'none';
  fontFamily: string;              // 中文字体栈
  background: string;
}

// draw(interpolatedRows, timeLabel, opts, ctx)
```

**绘制顺序(每帧)**:清背景 → 网格/轴线 → 从第 1 名到第 maxBars 名画条(含圆角矩形、条形标签、末端数值) → 标题/角标 → 时间大标签(半透明、大字,压在条形区上方一角)。

### 3.4 编辑器关键交互细节

- **配置自动同步到录制**:导出时以"当前配置"为唯一真源,录制前把配置+帧序列快照传给导出器,避免导出途中用户乱点导致状态漂移;
- **变速/拖动**:拖动进度条时应跳到最近整时间点并重算(避免半帧残影困扰用户);播放中可变速;
- **首帧预览**:未点击播放时展示第 0 时间点静态图。

### 3.5 录屏与导出链路(关键技术点)

```ts
// 伪代码:导出流程
const out = document.createElement('canvas'); // 横屏默认 1920×1080,不挂到 DOM
out.width = 1920; out.height = 1080;          // 竖屏需求则 1080×1920(仅此处 + 导出预设)
const stream = out.captureStream(30);        // 30fps
const rec = new MediaRecorder(stream, { mimeType: 'video/webm;codecs=vp9',
                                        videoBitsPerSecond: 8_000_000 });

const tick = (frameMs: number) => {           // 用 performance.now 驱动真实时长
  const frame = buildInterpolatedFrame(progressFromElapsed(frameMs));
  renderer.draw(frame, out.getContext('2d'));
  if (progress < 1) requestAnimationFrame(tick); else rec.stop();
};
rec.start();
requestAnimationFrame(tick);
// rec.onstop → blob(webm) → ffmpeg.wasm 转 mp4(H.264, yuv420p, faststart)
```

要点:
1. **码率**:`videoBitsPerSecond` 建议 6–12 Mbps(1080p30),数值文本多时给高;
2. **mimeType 探测**:`MediaRecorder.isTypeSupported('video/webm;codecs=vp9')` 依次降级 vp8/h264(见 §9 风险);
3. **时间基准**:录制与预览统一用"墙钟时间 × 倍率"推进进度,而不是按帧计数——这样变速不会丢时间,暂停恢复不跳帧;
4. **隐藏高清画布**不进 DOM,避免被 CSS 缩放;录制前 `document.hidden` 时 requestAnimationFrame 会暂停 → 提示用户保持标签页在前台,或改用 `setTimeout(…, 1000/30)` 兜底;
5. **导出总时长预算**:时间点数 N、每段时间 S 秒 → 总时长 ≈ N×S + 头尾各 0.5s 定格;N=50、S=0.6 时约 31 秒,合理。

### 3.6 样式与字体(中文视频刚需)

- 中文字体栈:`"PingFang SC","Microsoft YaHei","Noto Sans SC",sans-serif`;canvas 绘制大号数字/时间建议用等宽感字体避免跳动:`"DIN Alternate","Roboto Mono",…`;
- **字体加载**:中文 web font(如 Noto Sans SC)体积大,首版直接用系统字体,避免 Canvas 使用未加载字体导致的"录制里中文缺失/回退闪烁"问题;若自定义字体,用 `document.fonts.ready` 后再开录;
- 颜色方案:内置 3–5 套(Flat UI、期刊风、高对比深色),实体→颜色哈希分配后不可变(颜色跟着实体走,排名变了颜色不变)。

## 4. 后端设计(Node.js + TypeScript)

### 4.1 职责边界(务必克制)

| 做 | 不做 |
|---|---|
| 项目/数据/配置/作品的 CRUD | 渲染视频、合成音频、转码(浏览器端做) |
| CSV/XLSX/JSON 上传入库与基础校验(可前端先行校验) | 业务级的复杂分析 |
| 静态资源与产物文件存档(存磁盘,记录路径) | 用户体系/鉴权(单机单用户,明确不做) |
| `/api/ai/*` 转发至 **DeepSeek**(二期,key 只存后端) | —— |

> 因为"渲染在浏览器",后端永远不碰 ffmpeg/matplotlib。若日后出现"定时批量出片"需求,再新增一个 worker(可 headless 浏览器或改后端逐帧渲染),届时核心的"帧序列 + 渲染配置"数据模型不变,直接复用。

### 4.2 技术栈

- Node.js ≥ 20 + TypeScript;HTTP 框架 **Fastify**(比 Express 快、TS 友好、schema 校验内置)或 Express(生态更熟,二选一即可,方案按 Fastify 写);
- ORM:**Prisma**(迁移/类型生成一体)或 **Drizzle**(更轻);以下 DDL 以 SQL 原生口径给出,两者皆可映射;
- 校验:`zod`(入参校验,与前端共享类型);
- 文件:产物视频保存到 `./storage/`(本地),表里存相对路径;远程部署时换成对象存储,仅改一层 repository。

### 4.3 REST API 设计

资源与端点(v1,前缀 `/api/v1`):

| 资源 | 方法/路径 | 说明 |
|---|---|---|
| 项目 | `GET /projects` · `POST /projects` | 列表 / 新建(标题、初始配置) |
| 项目 | `GET/PATCH/DELETE /projects/:id` | 读/改配置(整包 JSON)/删 |
| 数据 | `POST /projects/:id/datasets/import` | multipart 上传 **CSV / XLSX / JSON 长表**;或提交 `{ sourceUrl }` 让后端抓取(政府公开数据,见下) |
| 数据 | `GET /projects/:id/datasets` · `GET /projects/:id/datasets/summary` | 取回显 / 元信息(行列数、时间范围、实体数、缺失统计) |
| 数据 | `DELETE /projects/:id/datasets` | 清空重导 |
| 数据源 | `GET /datasources` | 内置常用政府公开统计入口备忘(国家统计局等),按实际视频主题逐步扩充 |
| 配置快照 | `POST /projects/:id/snapshots`(可选) | 导出前固化渲染配置与帧序列 hash |

响应约定:统一 `{ data }` / `{ error: { code, message } }`;分页 `?page=&pageSize=`;写操作返回 201/204。错误码示例:`E_CSV_PARSE`、`E_EMPTY_TIMESERIES`、`E_NOT_FOUND`。

### 4.4 SQL 表设计(核心交付物)

设计口径:**单机单用户定稿 —— SQLite 即为最终数据库**(零配置、单文件易备份)。DDL 按可移植口径书写:若将来确需切 PostgreSQL,仅改类型写法(见注释),表结构不变。**时序数据用"长表"**(time, entity, value 各一行),这是 bar race 的标准查询与扩展形态。

```sql
-- 1) 项目表:一个项目 = 一条"可出片的视频配置"
CREATE TABLE projects (
  id            INTEGER PRIMARY KEY,          -- PG:改用 BIGINT GENERATED ALWAYS AS IDENTITY
  title         TEXT    NOT NULL DEFAULT '未命名项目',
  description   TEXT,
  config        TEXT    NOT NULL DEFAULT '{}',-- 渲染配置 JSON:标题/条数/配色/时长/分辨率等
  dataset_hash  TEXT,                          -- 导入数据内容的哈希,用于快照比对
  created_at    TEXT    NOT NULL DEFAULT (datetime('now')),
  updated_at    TEXT    NOT NULL DEFAULT (datetime('now'))
);

-- 2) 时序数据:长表 (time, entity, value)
CREATE TABLE time_series (
  id          INTEGER PRIMARY KEY,
  project_id  INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  time_key    TEXT    NOT NULL,               -- '2019' / '2020-01' / 'Q3' / '第1期' 均可
  time_order  INTEGER NOT NULL,               -- 时间排序依据(第 0/1/2… 期)
  entity      TEXT    NOT NULL,               -- 条目标识
  value       REAL    NOT NULL,
  UNIQUE (project_id, time_order, entity)
);
CREATE INDEX idx_ts_project ON time_series(project_id, time_order);

-- 3) 实体元数据(可选):颜色锁定、是否启用、别名
CREATE TABLE entities (
  id          INTEGER PRIMARY KEY,
  project_id  INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  entity      TEXT    NOT NULL,
  color       TEXT,                            -- '#e74c3c',NULL=按方案自动分配
  enabled     INTEGER NOT NULL DEFAULT 1,
  UNIQUE (project_id, entity)
);

-- 4) 导出/作品记录
CREATE TABLE records (
  id          INTEGER PRIMARY KEY,
  project_id  INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  config_snapshot TEXT NOT NULL,              -- 导出时的完整渲染配置 JSON
  file_path   TEXT,                            -- 产物相对路径;上传到后端时非空
  format      TEXT    NOT NULL DEFAULT 'mp4',
  width       INTEGER NOT NULL DEFAULT 1920,
  height      INTEGER NOT NULL DEFAULT 1080,
  fps         INTEGER NOT NULL DEFAULT 30,
  duration_ms INTEGER NOT NULL DEFAULT 0,
  size_bytes  INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT    NOT NULL DEFAULT (datetime('now'))
);

-- 5) AI 任务表(二期,DeepSeek)
CREATE TABLE ai_tasks (
  id INTEGER PRIMARY KEY,
  kind TEXT NOT NULL,                       -- 'gen_data' | 'title' | 'narration' ...
  model TEXT NOT NULL DEFAULT 'deepseek-chat',
  project_id INTEGER REFERENCES projects(id) ON DELETE SET NULL,
  request TEXT, response TEXT, status TEXT DEFAULT 'pending',
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

设计要点:

- **时间排序独立于标签**:宽表数据里年份天然有序,但"Q1…Q4""第1期…"等需要显式顺序,所以加 `time_order` 由导入器按出现顺序/字典序赋值,避免前端猜语义;
- **不存"当前排名"**:排名是渲染期由 `ORDER BY value DESC` + 插值实时算的,存了就脏;
- **一次导入全量替换**该 project 的 `time_series`(事务内 delete+insert),`dataset_hash` 用内容哈希做幂等;
- 一个 CSV 文件 ≤ 10 万行时 SQLite 毫无压力;超过再考虑批处理导入。

## 6. 渲染与动画算法(实现必读)

### 6.1 bar chart race 的插值与排序算法(推荐实现)

朴素做法(每帧按插值后的值重排)会产生**条形来回抖动**(值接近的实体互相交换时,插值中段 y 跳动)。推荐做法:

1. 对任意相邻两个时间点 A、B:
   - 排序 A、B 各自取值前 `maxBars` 名的实体集合,取**并集**(含"即将上榜"与"即将跌出"的条);
   - 实体 A、B 两端的值已知 → 当前帧值 = `lerp(vA, vB, easedT)`;
   - 当前帧排名 = 对并集实体**按当前帧值降序**排序 → 得到每条的 Y 位置;
   - 条形 x 长度 = 当前帧值映射到绘图区宽度(`d3-scale` linear);
2. 条自身带稳定 id(实体名),Vue/Canvas 不关心 DOM 复用,直接每帧全量绘制即可;
3. 排名并列时按实体名字典序稳定(保证幂等画面);
4. 实体只在一个时间点出现:视为另一端值为 0 或"未上榜"(配置可选"仅显示两端都在榜的条")。

> 抖动规避的本质:**长度插值**产生平滑增长,而 **Y 由插值后的值实时排序决定**——当两条数值很接近时确实会来回换位,这是 bar race 的正常观感;真正要避免的是"条数变化瞬间整组跳变",靠上面"取并集 + 0 值补位"解决。

### 6.2 时间轴与"时间标签"

- 总时长 = `(N-1) × secondsPerStep + headHold + tailHold`(头尾各定格 ~0.5s);
- 播放进度 p ∈ [0,1] → 换算成 (整数步 k, 步内进度 t);标签文本 = `k` 与 `k+1` 两个标签的插值:
  - 若 time 语义是"区间/时点"(如年份),标签用**当前步的标签**(切步时刷新)——最符合观众认知;
  - 若 time 是连续数值(可选项),显示 `lerp(parse(k), parse(k+1), t)` 保留一位小数;
- 渲染大字时间用等宽数字字体并固定基线,避免数字位数变化(999 → 1000)时画面抖动。

### 6.3 两个渲染循环的分工

| 循环 | 画布 | 驱动 | 用途 |
|---|---|---|---|
| 预览循环 | 可见 canvas(自适应窗口) | rAF + 用户控制 | 交互、调参 |
| 导出循环 | 隐藏 1920×1080 canvas | 独立 rAF/setTimeout 兜底 | 录屏 |

- 导出期间**冻结配置**(读快照),预览区显示"正在导出,预览已暂停";
- 导出用独立的引擎实例与状态对象,与预览零共享可变状态;
- 帧率控制:导出按目标 fps 均匀推进(每帧推进 `secondsPerFrame = 1/fps` 的墙钟秒,再用 elapsed 累计),比"每 rAF 画一帧"更稳(高刷屏不会录出 120fps 变速视频)。

### 6.4 性能预算

- 1080p、30fps、30–50 根条、纯色矩形 + 文本:每帧 Canvas 绘制 < 2ms,主线程无压力;
- 若开启阴影/圆角,控制在条数与阴影半径上(避免每帧 blur 开销);
- 长视频(≥3 分钟):WebM blob 可能数百 MB,转码内存峰值注意;建议给用户"码率/时长预估"提示,或切片录制(可选)。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Safari 的 MediaRecorder 不支持 webm/vp9 或没有该 API | 无法导出 | 检测 `isTypeSupported`,不支持时提示用 Chrome/Edge;或后端接受 webm 文件转 mp4(备选路径) |
| 录制中标签页切后台,rAF 停摆 | 视频卡顿/变短 | 提示保持前台;导出循环用 setTimeout 兜底并做"墙钟进度"校验(§6.3) |
| ffmpeg.wasm 首载体积大(~30MB)/内存峰值 | 首导慢 | 懒加载 + 首次下载进度提示;码率档位限制 |
| 中文 web 字体未加载导致录制缺字 | 成片缺陷 | 默认系统字体;自定义字体等 `document.fonts.ready` 并预绘首帧 |
| 数据异常(空值、爆值、实体过多) | 画面误导 | 导入期校验报告;value 缺失行提示补 0 或剔除;实体数 >500 建议聚合 |
| 政府源 CSV 编码(GBK/UTF-8) | 中文乱码或解析失败 | 导入时按 BOM/内容探测编码;GBK 先 `TextDecoder('gbk')` 转码再交 papaparse |
| 浏览器内存随长视频膨胀 | 崩溃 | 码率与时长预估提示;后续加"切片录制再拼接" |
| SQLite 并发写锁 | 单机单用户基本无感 | 后端保持单写连接即可;无需切库(§11) |
